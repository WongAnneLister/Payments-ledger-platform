# PR06 business payment implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Authenticated, durable and idempotent business payment create/query/cancel using the existing provider ports.

**Architecture:** Short PostgreSQL intent/claim/writeback transactions surround transaction-free provider calls. The accepted frozen PR06 contract defines the scope; durable unknown operations await PR07 recovery, and no PR08/PR10 side effects are introduced.

**Tech Stack:** Java 21, Spring Boot/JDBC, Flyway PostgreSQL, JUnit/Testcontainers and the existing Fake/Stripe ports.

## Task 1 — Strict request boundary and customer entry (parent)
- [x] Write PaymentRequestsTest for canonical defaults/metadata ordering, exact integer parsing, unknown fields, URL validation, quantity/key/text bounds and reserved metadata. Run focused Maven tests to observe missing behavior, then implement PaymentRequests.
- [x] Implement PaymentController using trusted AuthenticationFilter context, create/read/cancel scopes, Location/replay headers and stable errors. Handle malformed JSON as VALIDATION_ERROR without echoing payloads. Add controller tests independent of the storage implementation.
- [x] Add a minimal same-origin static test page: application key only in memory, create, explicit hosted redirect and result query. Returning to the page does not itself declare success.

## Task 2 — Durable payment core (implementation subagent)
- [x] Write a PostgreSQL migration/intent test first and demonstrate its failure; implement V4__business_payments.sql and PaymentService/PaymentExecutor/PaymentRepository (split by responsibility).
- [x] Composite scope FKs; order/API independent uniqueness; immutable snapshot/provider command; operation XOR with refund blocked; observation append-only; runtime grants.
- [x] Transactional create validates authoritative active price/policy and amount with Math.multiplyExact; same-key replay precedes current pricing checks. Persist all intent objects together.
- [x] Executor claim and conditional writeback around transaction-free CheckoutPort calls; retain all evidence; persistent PREPARED queue drained by worker, unknown outcomes not resent.
- [x] Authoritative scoped refresh records attempts and sticky capture; cancel guarded by query evidence, persisted intent and exact expire semantics. Return current four-dimensional PaymentResource.
- [x] Run isolated PostgreSQL tests: 100 calls synchronized at ingress (sufficient distinct connections/tasks), same-order/different-key, payload conflict, immutable policy, runtime restrictions, unknown/crash tasks, multiple attempts/cancel race; both empty and V3→V4 migration.
