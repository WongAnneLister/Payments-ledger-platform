# PR14 Payout and simulated bank evidence design

The frozen PR14 prompt, payout state machine, accounts and AC-V1-26/27 define the approved scope. Ingestion and read-only query are mandatory; no new external money write is required. Continue the established local feature commit workflow.

PayoutService keeps scoped raw provider observations, immutable financial facts and source links, allocation counters and cases. Payout(60) precedes bank line(65), BT/financial event(70), globally sorted ledger accounts(80). FinancialReplayService discovers and locks the payout before locking the BT, then delegates actual posting to PayoutService. Stable PR10 BT keys remain the unique external money event keys. Source queries and list pagination perform external reads outside local transactions, persist evidence and durable cursors, and reject malformed/version-changing pages without advancing completion.

A verified outgoing BT debits BANK_PAYOUT_IN_TRANSIT by principal and credits PSP_FUNDS; signed fees are separate. A failure BT credits available transit first; overlap is credited to SUSPENSE and a conflict remains visible. paid changes only provider state. Unknown/new contradictory terminal states preserve observations and create cases. Counter amounts must be supported by immutable sealed journals. Unavailable BT dependencies remain pending.

BankStatementImporter accepts only schemaVersion=1 and evidenceType=SIMULATED_BANK_EVIDENCE, explicit trusted test ProviderScope, stable fixture ID and bank account reference, half-open UTC coverage, currency, complete flag and immutable line IDs. CREDIT and RETURN lines have positive gross principal, separately declared fees, booking instant and explicit payoutReferences. These references support a verified batch line split among named payouts; no FIFO inference. Reimport is idempotent only for identical canonical payload; source identity collisions reject atomically.

BankMatcher locks payout then bank line, checks same scope/currency, named reference, arrival-date window of +/-7 UTC days, positive amount, line remaining capacity and payout transit. Each payout/line/kind pair is consumed once with stable event key and exact facts; a retry with different amount conflicts. Credit debits cash and bank fee expense, credits transit; cumulative fee allocation uses difference of floor(fee*consumed/principal), so all split allocations total actual fee exactly. RETURN evidence can settle a prior overlap: debit SUSPENSE, credit BANK_CASH, reduce net bank allocation and increase returned principal, without deleting old journals. Overlap or mismatched evidence cannot double allocate principal. No bank evidence is WAITING_EVIDENCE; conclusive short receipts require complete coverage and matching identity and are exposed as evidence for PR15.

Automatic membership is obtained only from provider payout-filtered BT pages and stored separately from payout's own negative BT. Manual payouts never obtain guessed membership. Pages, source evidence, test fixture label and completeness remain available to PR15/16; no public import API here.

Verification includes exact 5700 transit/cash/return examples; signed fees; partial and split lines; duplicate imports/matches; concurrency on real PostgreSQL connections; rollback; source identity immutability; upgrade V11->V12 and runtime privileges; webhook ACK; query/replay path; wrong currency/reference/date; incomplete/short evidence; auto/manual membership. Fixture-only evidence and skipped real account capability are reported explicitly. Final full clean verify and source hashes gate local commit.

## Review refinements

Membership read runs pin the immutable payout observation UUID; a newer source observation opens a fresh official membership run after an earlier complete/empty page. V13 composite scope and source FKs plus private provenance guard prohibit cross-provider/run/observation ancestry and manual membership. Membership comparison uses shared FinancialFacts immutable money projection, normalized through stored JSON integer representation, preserving normal availability updates. Query priority rotates before an unavailable or throwing external read.

Quality review refinement: SHORT_RECEIPT requires booking dates eligible for this payout and an actual match allocation to this payout, not merely a complete shared line consumed by another payout. Out-of-window shared evidence remains WAITING_EVIDENCE.
