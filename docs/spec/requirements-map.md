## 0. 命名空间与效力

1. 本项目**唯一有效的验收命名空间是 `AC-V1-01` 至 `AC-V1-38`**。旧文档中的 `AC-01`、`AC-02`…… 等 `AC-xx` 编号**全部废止**，不得在代码注释、测试名、提交信息、报告或简历材料中引用；发现引用即视为文档缺陷并必须修订。
2. 不变量固定为 `I-01`～`I-07`，故障模式固定为 `F-01`～`F-08`，不新增第八项不变量或第九类故障。
3. 需求编号沿用 PRD：`FR-PAY-01/02/03/04`、`FR-REF-01/02`、`FR-SHARE-01`、`FR-DIS-01`、`FR-PO-01/02/03`、`FR-REC-01/02/03`，外加横切项 `X-SEC`（认证与权限）、`X-OPS`（运营与审计）、`X-OBS`（可观测性）、`X-EVID`（工程证据）。
4. 本文件是索引，不是规则来源。业务规则冲突时以 PRD 为准；本文件与 PRD 不一致属于必须同步修订的缺陷，不允许"挑选方便的规则"。
5. 本文件的存在**不表示**任何验收已执行。全部 `AC-V1-*` 的 `executionStatus` 初始值仍为 `NOT RUN`。

三条必须写进实现与报告的限定：

- **I-02**：`(scope, event_key)` 唯一键只能证明"至多一次"。"所有已接受事件都有 Journal、且没有孤立 Journal"必须由 PR15 的双向覆盖扫描证明，不能用唯一约束替代。
- **I-06**：本地累计本金分配 ≤ 已转出本金，这部分在 PR14 的匹配事务内即可拒绝；"在途 + 已确认银行到账 + 已确认返还 = 已转出本金"的完整外部守恒必须等银行与 PSP 证据齐备，缺证据时为 `INCOMPLETE`，不是 `PASS`。
- **I-07**：跨域归属拒绝（FK/CHECK）与余额投影独立重建是两个不同验证，任何一个通过都不能代表另一个通过。
