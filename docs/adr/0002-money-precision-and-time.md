# ADR-0002：精确金额与时间/时区处理

状态：Accepted（PR00 冻结） · 日期：2026-09-10

## 背景

金额与日期是资金系统两个最常见的静默错误来源：

- 浮点数使 `0.1 + 0.2 != 0.3`，分润按比例计算时会产生不可复算的尾差。
- 不同币种的最小单位不同（USD 指数 2、JPY 指数 0），把"元"和"分"混用会造成 100 倍错误。
- "业务日"不等于 UTC 日。用"固定减 24 小时"计算日期边界会在 DST 切换时漏掉或重复一小时的数据。

## 决策

### 金额

| 规则 | 内容 |
|---|---|
| 表示 | **最小货币单位的 64 位整数**（`bigint` / Java `long`），字段名统一以 `_minor` 结尾 |
| 禁止 | 浮点（`float`/`double`/`REAL`）出现在任何金额路径；JSON 中金额为整数而非字符串小数 |
| 换算 | `currency_config.minor_unit_exponent`（USD=2、JPY=0），`CHECK (0 <= exponent <= 4)` |
| 溢出 | 一律使用 `Math.addExact` / `Math.multiplyExact`；溢出抛异常并拒绝请求，不静默回绕 |
| 跨币种 | 单张 Journal 内币种必须一致，由 FK + CHECK 在提交时强制；**禁止**不同币种金额相加 |
| 负值 | `PSP_FUNDS` 允许为负（真实存在）；分润计提禁止为负；请求金额必须为正 |

**舍入政策（冻结）**：分润 `cap_i = floor(eligibleBase * rateBps_i / 10000)`，**各合作方独立计算，向下取整，余数归平台**。

必须按**当前累计 base** 计算 cap，**不能**逐笔退款取整后相加——否则碎片化退款会产生舍入套利：

```text
正确：  eligibleBase=6000, rate=2000bps → cap = floor(6000*2000/10000) = 1200
错误：  退款拆成 4 笔各 1000，每笔单独取整后累加 → 可能得到 ≠1200 的结果
```

整数运算顺序固定为**先乘后除**（`eligibleBase * rateBps / 10000`），不得先除后乘。

### 时间

| 规则 | 内容 |
|---|---|
| 存储 | 一律 `timestamptz`（UTC 瞬时），Java 侧用 `Instant` |
| 禁止 | `LocalDateTime` 出现在持久化与跨进程传递路径 |
| 业务时区 | 配置项，默认 `UTC`，可配 `Asia/Tokyo` |
| 业务日 → UTC | 用 `ZoneId` + `LocalDate.atStartOfDay(zone).toInstant()` 生成**明确的 UTC 半开区间** `[start, end)` |
| 禁止 | 用"固定减 24 小时"或"减 86400 秒"计算日期边界 |
| 时钟 | 一律注入 `java.time.Clock`，测试可控；禁止直接调 `Instant.now()` |

**DST 处理**：业务日转 UTC 区间时，由 `ZoneId` 规则处理夏令时跳变。一个业务日的 UTC 跨度可能是 23、24 或 25 小时，这是**正确**行为，不是 bug。

**T+1 的含义**：次日运行的发现与核对任务。它**不是**宣称 Stripe 次日结算，也**不是**所有异常最多一天必恢复。

## 被否方案

| 方案 | 为什么否 |
|---|---|
| `BigDecimal` 表示金额 | 仍可能引入非整数尾数；序列化与数据库类型映射易出偏差；比较需注意 scale。整数最小单位更简单且与 Stripe 的 `amount` 语义直接对齐。 |
| 金额用字符串小数传输 | 需要在边界反复解析，且把"多少位小数"的判断推给客户端。 |
| 统一假设 2 位小数 | JPY 等零小数币种会被放大 100 倍。PRD 明确要求 JPY 作为独立 fixture 验证。 |
| 用 `date` 类型存业务日并直接比较 | 丢失时区信息，无法与 `timestamptz` 的 BT `created` 做正确区间比较。 |
| 所有时间按 UTC 日切分，不引入业务时区 | PRD 要求默认 UTC、可配 `Asia/Tokyo`；报告的"业务日"必须对运营有意义。 |

## 后果

**正面**

- 分润、退款、余额全部可手算复现（见[手算示例](../ledger/posting-examples.md)）。
- 属性测试的独立 oracle 可以用纯整数模型，不需要容差比较。
- DST 与跨时区边界成为可测试的明确输入，而非隐藏假设。

**负面与缓解**

| 负面 | 缓解 |
|---|---|
| 展示层需要按币种指数格式化 | 统一格式化工具，指数来自 `currency_config` |
| 整数除法丢弃余数需要明确归属 | 政策冻结为"余数归平台"，并在分润页展示 |
| 溢出检查增加样板代码 | 封装 `Money` 值对象，集中做 `addExact` |
