# PR13 争议处理

关联：[状态机](../state-machines/dispute.md)、[分润](revenue-share.md)、[退款](refunds.md)、[锁顺序](../adr/0007-lock-order-and-isolation.md)。

## 状态和资金

争议查询与已验签 Webhook 保存原始提供方状态、关联 Charge、金额、币种、证据截止时间和 BT ID。个人抗辩材料不进入 Webhook 快照；本期不提交抗辩、不提供真实资金写接口。证据不完整时保留待补齐记录，禁止凭金额猜归属。

开放 inquiry/warning 也会阻止新的普通退款并撤回全部内部分润，但没有 BT 时不减少 PSP。正式争议扣款 BT 才借记争议应收及实际费用，贷记 PSP。败诉把尚存应收转为内部损失，PSP 不再扣一次。胜诉状态本身也不增加 PSP：新返还 BT 先冲应收，再冲此前损失，超额进 SUSPENSE 并调查。费用按实际带符号金额记账，不能凭胜诉自动退费。

收款10000、收款手续费300、分润20%的例子：PSP9700、分润2000。争议本金3000、费用1500扣款后 PSP5200、应收3000、分润0；败诉后应收转损失3000，PSP仍5200；胜诉本金返还3000后PSP8200，费用1500保留。资金证据全部入账、无其他争议或冲突时才恢复分润2000。

## 原子性和恢复

争议规范观察、退款控制、分润调整与新凭证在同一事务内提交。多个争议共同阻断，最后一个阻断清除后才恢复分润。已解决终态收到更新的矛盾或未知状态时，原规范状态与新观察均保留，并创建阻断调查记录；旧的过期观察不会倒退终态。已提交退款义务或外部退款与争议重叠时，两份事实都会保留并冻结调查，不把争议本金加到退款 R。

资金先到时，现有财务 Worker 查询对应争议并重新重放 BT；返还先于扣款时保留依赖，不凭空冲销未发生的应收。已知未解决争议由查询 Worker 补查，包含败诉后 late win。每批最多25条，失败条目按持久化尝试时间轮转。查询发生在数据库事务外，使用独立财务调度器。启用条件与财务导入相同：worker角色、`platform.financial-ingestion.enabled=true` 和可信组织/环境/Provider账户配置。争议补查默认300000ms，可用 `platform.dispute.poll-ms` 调整。

内部 scoped 查询为PR16运营入口准备，不新增公开管理API。所有凭证与资金事实追加保存，不能删除旧账或直接改余额解除阻断。

验证使用真实 PostgreSQL 事务和可控 Provider/HTTP fixtures。真实 Stripe 争议实验为 **NOT_RUN**，fixture结果不能当作真实账户实验。[PR13 验证记录](../evidence/pr13/README.md)记录实际测试、分录及未运行项。
