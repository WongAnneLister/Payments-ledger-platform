# PR04 Provider ports and persistent fault simulator

Scope follows the already frozen PR04 prompt and provider contract. Implement only owned DTOs, ports and a deterministic durable FakeStripeProvider. No business HTTP APIs, payment/refund business tables, ledger writes, Stripe SDK or real network requests.

## Design

Use a separate JSON state file per simulation, guarded by an OS file lock and an in-process lock, with forced temporary-file writes and atomic replacement. Every simulated remote call reloads state under the lock and commits independently from the application's database transaction. A corrupt file fails closed: verify a canonical SHA-256 checksum stored in the same atomic envelope before processing, plus typed structural validation. This detects accidental corruption, not a malicious editor who can recompute the checksum. Response evidence digests use canonical field order across JVMs. This is a bounded local fixture store, not a distributed production database or power-loss durability claim. An explicit persisted seed, simulated UTC clock and retention duration make runs replayable; constructor configuration must match an existing store. IDs derive from seed and a persisted sequence. Clock advancement never sleeps or moves backwards.

Ports use owned immutable DTOs and ProviderCallResult classification/evidence. No SDK types. Scope includes organization, environment, provider account and livemode; Fake rejects live. Checkout creation records a session and PI but no capture. Explicit test controls drive authentication, failed attempts, successful capture and expiry races. Metadata is assigned separately to session and PI. Refund creation validates the captured charge and remaining remotely refundable amount, creates a refund with a separate effect log; pending/failed status and debit/return BT are independently controlled.

Each scope/operation/idempotency-key caches the canonical request and result until the configured finite expiry. Matching replay reuses the original payload; mismatched parameters conflict. Expiry allows a new operation and therefore new effects. Failed-before-send has no accepted effect; accepted-response-lost commits objects/effects before TIMEOUT_UNKNOWN. A cached transient failure can be scripted explicitly. All calls retain a digest and classified evidence, even timeout and rejection. Counters and effect records are persisted independently of local tables.

FailureScript queues target scope + operation + object ID or operation key. Supported outcomes: before-send failure, accepted response loss, crash after commit, transient empty, transient error, cached transient error, rate limit, definitive reject, auth required, contract mismatch. Recovery callers must query/reuse keys themselves; Fake never auto-recovers from local business records. Ports reject calls made inside an active local Spring transaction.

Read fixtures cover Charge attempts, BT pages in fixed [createdGte, createdLt) windows, visibility delays, pending→available changes, disputes, payouts, current balances and optional reports. Stable pagination is ordered by creation instant then ID and validates scoped/query-bound cursors. Manual payout membership queries are rejected. Current balances use independent fixture state, not the local ledger. Report capability defaults unavailable and is explicitly fixture-only when enabled.

Webhook events are persisted separately from delivery attempts. Explicit test controls enqueue missing, duplicate or reordered deliveries; no automatic HTTP send. Local fixture signing/verifying uses a clearly fake scheme over original bytes, not a claim about Stripe signatures. Runtime bean wiring is opt-in under the test profile; management is a Java test harness only, with no HTTP management routes.
