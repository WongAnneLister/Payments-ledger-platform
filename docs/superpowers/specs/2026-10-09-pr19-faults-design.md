# PR19 可重放故障矩阵设计

基线：main `c600b15`。依据冻结 PR19 提示词和 AC-V1-35/F-01–08；本次用户“继续做 PR19”授权执行既定范围。

## 范围与设计选择

沿用现有生产服务、FakeStripeProvider 的独立持久效果账、真实 PostgreSQL 16 和 Kafka 3.9.0 的隔离容器。新增测试驱动器、八类实验、严格证据运行器与 CI 矩阵；不改变资金、身份或状态规则。相较只汇总旧测试，本期实际重放并保存每个故障窗口；相较完整部署系统，在测试 classpath 的子 JVM 中构造生产组件，便于确定触发窗口、强杀进程并复原。子 JVM 与部署集群的区别必须声明。

F-01–05 驱动已有恢复、Webhook 与 Provider 路径，分别保留已知操作、仅订单、无订单；同 event 与同财务事实重复；依赖乱序和旧状态；正文/签名/端点 secret/时效/持久化失败；支付和退款的发送前、受理后以及幂等窗口过期样本。F-06 用真实子进程终止验证提交前后、远端调用前后、Inbox/Outbox/消费者提交与 ack 之间，并保留旧 lease fencing 的受控样本。F-07 使用真实 Kafka 暂停/恢复、发送后未标记、数据库提交后未 ack 的窗口，独立模拟商户库检查效果。F-08 在至少两个 JVM 中通过文件屏障同步进入生产事务，竞争支付幂等、双退款、退款与分润/争议、银行分配和同 BT 导入。

## 证据与验收

每个子实验独立保存 Test ID、variant、固定时钟/seed、输入数据和操作键、注入点、恢复入口、注入/恢复时间线、中间与最终数据库/Provider/消息证据、请求/受理/Webhook/转换/Journal/商户效果/Provider 资金效果计数、实测恢复耗时和限制。共用写入器先标 FAIL，只有全部断言通过才标 PASS；异常仍持久化失败记录。

资金断言检查 Journal 借贷平衡及规范事件唯一性、退款 R+H<=C（外部冲突需单列）、分润 cap、银行分配不超本金、投影独立重建。外部资金效果从 Fake 独立日志读取，不从 payment 行数反推。商户效果从独立模拟商户库读取。真实 Stripe、真实银行和线上资金不参与；不读取 .env。

运行器按 F-01–08 完整集合和每类必需 variant 验证，不允许漏测或跳过被写成 PASS。报告保存实际环境、命令、SHA256 输入清单、完整构建退出码与实际 counts。CI 每类可单独重放并总体验证，失败也上传产物。未执行远程 CI 为 NOT RUN，能力不足为 BLOCKED。恢复时间只描述当前隔离环境，不承诺外部最终完成时限。
