# PR17 pages and observability

Approved scope: the user requested the already-defined PR17 milestone. The frozen PR17 prompt, AC-V1-15/32, ADR-0003/0006 and PR16 contract define behavior. Existing Chinese static pages set the language/style; implementation choices remain within that scope.

## Architecture and alternatives

Extend the existing same-origin static HTML/CSS/JavaScript application. This keeps deployment in the API artifact and reuses all trusted APIs. A new SPA framework would add a build/runtime without a requirement; server-generated finance views would duplicate the API boundary. Use small shared modules for API transport, safe rendering/status models and page controllers. Node's built-in runner tests pure browser logic and async request ordering without third-party packages; real HTTP/PostgreSQL and actual browser smoke verify wiring.

## Customer and operations experience

Create a separate payment-result page that only queries the original /v1 payment and displays business/resolution/financial states. URL success/cancel flags and notifications are not payment proof. UNKNOWN/CONFLICT or failed refresh never invite a replacement payment. Preserve pending order identity and stable keys in the existing test page; credentials remain memory-only and are cleared on identity change. Session storage may contain original resource/draft identity only.

Create one operations console with navigation for Payment Detail, Refund Detail, Dispute Detail, Ledger Explorer, Balance Reconciliation, Payout Detail, Revenue Share and Exceptions/Tasks, plus metrics and adjustment review. Every resource uses PR16 API; the browser has no database connection. General ops identity/role gates navigation, PARTNER_VIEWER only accesses its own share lines, and server authorization remains authoritative. Reconciliation/import/exception/retry/adjustment/approval forms retain exact body and stable idempotency key across uncertainty and replay, show independent author/reviewer, and refresh current GET state after a command rather than presenting a cached replay as current.

Use a restrained navy/teal/white internal-console design, responsive readable tables, labelled inputs, keyboard navigation and live error/loading notices. Human headings explain meanings; raw domain states and evidence IDs remain visible. Show order, hosted objects/attempts, provider facts, BTs, sealed Journal/Entry, simulated bank evidence and chronological traces with safe drilldown links. Missing or truncated evidence is explicit and does not become funding success. Keep currencies separate and display integer/minor-unit amounts without silently rounding int64 values. Latest-request generation/abort control prevents old responses or changed credentials from overwriting current state. Render untrusted strings through textContent; validate hosted HTTPS URLs and same-origin drilldowns.

## Observability

Add an API-profile GET /ops/observability protected by trusted OpsContext and OpsAuthorization.read(false), explicitly documented in OpenAPI. It reports scoped, read-only backlog/age gauges: unknown_payment_count/oldest_age, refund_reserved_age, webhook_lag, outbox_oldest_age, ledger_pending_evidence, unclassified_bt_count, trial_balance_failures, reconciliation_residual, payout_unmatched_age and share_cap_violations. Define exact persisted predicates, source times, seconds/count/minor units and missing-data semantics. Reconciliation residuals remain separated by run/provider/currency with outcome/completeness and source time; do not sum different currencies or let an absent report imply PASS. Micrometer binds bounded low-cardinality internal metrics; public actuator exposure remains health only. API aggregation never leaks foreign org/env, disabled currency or live facts. Errors expose unavailable status, not synthetic zero success. Alerts use explicit documented thresholds and say observational alerts do not change money or reconciliation truth.

Emit allowlisted structured domain correlation events with requestId/businessOrderId/paymentId/operationId/providerRequestId/BT/event/Journal/runId where actually known. Never log raw credentials, full tokens, client secrets, card or bank payload, reason/body, arbitrary caller metadata or raw exception contents. Validate/suppress unsafe identifiers and test structured output with injected secrets. Use existing request MDC and supported Spring structured format; no provider call or financial mutation from observation.

## Verification and delivery

TDD tests prove UNKNOWN/partial evidence, contradictory states, stale response ordering, duplicate notifications, role/scope rejection, exact amount handling, XSS-safe rendering, command key stability/replay refresh, metric predicates/ages/foreign scope, and structured redaction. Actual browser smoke/screenshots must show customer UNKNOWN and representative ops trace/alerts; HTTP checks also prove worker cannot expose pages/API. Record Node tests, Java focused/full runs, API/contract mappings, metrics and redacted log samples, actual screenshot origin, source hashes, reviews and NOT_RUN limitations. No new real provider money or live mode. Implement on codex/pr17-ui based on fc09cb2; local commit only until the user separately requests merge/push.
