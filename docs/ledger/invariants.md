# 七项资金不变量：提交强制与独立核对

版本：PR15 · 状态：本地提交约束与七项夜间扫描已实施；外部一致性依赖完整、可比的独立证据

运行入口、报告版本和证据边界见[对账运行说明](../runbook/reconciliation.md)。七项扫描把 I-01/I-02 合并为封存与双向覆盖检查，另列 BT 页面/事件覆盖；不会增加资金不变量。

关联：[PRD §10](../product/payment-platform-prd.md) · [验收 §3](../product/payment-platform-acceptance.md) · [账本科目](accounts.md) · [手算示例](posting-examples.md) · [需求映射 §3](../spec/requirements-map.md)

**恰好七项，不新增"第八项"。** 它们的作用范围不同：本地不变量可在提交时拒绝；外部一致性只能在证据完整且截止点一致后核对。

> **不能宣称"提交事务即可保证 Stripe 与银行一致"。** 这是本项目最重要的诚实边界。

## 1. 总表

| ID | 精确定义 | 提交时强制 | 独立扫描/证据核对 | 失败行为 |
|---|---|---|---|---|
| **I-01** 借贷平衡 | 每张已过账凭证同币种 `sum(debit)=sum(credit)`，至少两条有效分录 | 受控一次性过账；延迟约束触发器校验**最终**分录集合；拒绝空凭证、单行、不平衡、非法金额、封存后补插 | 夜间逐凭证重算 + 全账试算；属性与故障序列 | 回滚本次入账并报警；修正必须新事件、新凭证 |
| **I-02** 事件唯一入账 | 每个已接受规范化财务事件恰好一个 Journal | `(scope, event_key)` 唯一；事件与 Journal 同事务；重复返回既有结果 | **双向覆盖扫描**：已接受事件 ↔ Journal，查无漏记与孤立凭证 | 重复保持原结果；缺失/冲突进差错并有证据修复 |
| **I-03** 退款额度 | `NORMAL` 控制行中 `0<=R+H<=C`，且 C、R、H **各自非负** | 锁支付控制行 + 条件更新；预占、操作意图、分润变更同事务 | 重算 C/R/H；预占老化；外部退款冲突扫描 | 拒绝本地超额；**不**为维持 NORMAL 丢弃已证实外部退款 |
| **I-04** 分润上限 | 每合作方 `0<=S_i<=floor(eligibleBase*rate_i/10000)`，各比例合计 `<=10000` | 计提、退款预占、争议阻断与撤回按固定锁序同事务；稳定事件键 + 新凭证 | 读下单快照重算累计上限、有效计提与凭证覆盖；检验碎片化退款舍入 | 撤回/拒绝超额计提，保留完整账务链，**不改旧分录** |
| **I-05** PSP 资金守恒 | 同账户/环境/币种/余额域/截止点：本地 PSP 余额 = 期初 + 完整 BT 净变动，**且**与独立 Stripe 期末证据一致 | 已接受 BT 的单次入账与 PSP 投影同事务；禁止重复更新投影 | 完整分页 + 独立期末证据 + 范围/截止一致后外部核对 | 保留残差；缺证据 `INCOMPLETE`；**不制造平账分录** |
| **I-06** 出款守恒 | 单 payout 已转出本金 = 尚在途 + 已确认银行到账 + 已确认返还（含经验证调整）；费用单列 | 锁 payout/银行分配控制行；限制累计本金分配、银行行重复使用、到账/返还重叠；**可立即拒绝本地超额** | PSP 与银行证据齐备后核对完整现金路线；处理净银行费用、银行退回、跨日证据 | 超额拒绝；缺证据暂挂；短款/冲突进差错，**不双算**到账与返还 |
| **I-07** 隔离与可重建 | 一张凭证内组织/环境/币种一致；账户余额投影 = 期初 + 对应不可变分录；同一资金来源不跨域重复归属 | FK、账户范围与来源归属唯一约束；本地入账不跨域；仅 `LedgerPostingService` 更新投影 | **独立**扫描期初与分录重建并比较投影；扫描来源跨域覆盖与未分类项 | 拒绝跨域写；投影差异告警，以可审计重建纠正投影，**不改凭证迎合投影** |

## 2. 三条必须写进实现与报告的限定

PR00 特别冻结以下三点，防止把"部分保证"说成"全部保证"。

### 2.1 I-02：唯一键不能独自证明事件无遗漏

```text
UNIQUE (organization_id, environment_id, event_key)
    证明了：同一事件【至多一次】入账
    没有证明：所有已接受的事件【都已经】入账
```

"无遗漏"必须由 **PR15 的双向覆盖扫描**给出：

- 方向 A：每个 `status=ACCEPTED` 的 `financial_event` 都能找到对应 Journal → 否则是**漏记**
- 方向 B：每个 Journal 都能找到对应已接受事件 → 否则是**孤立凭证**

两个方向都必须扫，缺一不可。夜间检查中"已接受事件缺 Journal"判为 `FAIL`（验收 §8）。

### 2.2 I-06：本地上限可提交拒绝，完整守恒要等证据

| 部分 | 何时可判定 | 失败处理 |
|---|---|---|
| 累计本金分配 ≤ 已转出本金 | **匹配事务内即可拒绝** | `409` / 回滚，无残留 |
| 一条银行行不被重复消耗 | 提交时约束 | 同上 |
| 在途 + 已确认到账 + 已确认返还 = 已转出本金 | **须 PSP 与银行两侧证据齐备** | 缺证据 `INCOMPLETE`，**不是** `PASS` |

**不能把整项 I-06 简单归为"仅本地"或"仅外部"**（PRD §10 明确要求）。

### 2.3 I-07：隔离约束与独立重建是两个验证

| 子项 | 验证方式 | 通过不代表什么 |
|---|---|---|
| 跨域归属拒绝 | FK / CHECK 在提交时失败 | **不代表**投影正确 |
| 余额投影 = 分录重建 | 独立扫描器绕开生产投影路径重算 | **不代表**跨域约束存在 |

任何一个通过**都不能**代表另一个通过。测试必须分别给出证据（验收 §3）。

## 3. I-05 的三份可比输入

`I-05` 最容易被"用同一份错数据证明自己正确"蒙混过去。**至少需要三份独立输入**：

| # | 输入 | 能发现什么 |
|---|---|---|
| 1 | 期初 + BT 明细（导入的原始事实） | — |
| 2 | 本地不可变账本 / 重建余额 | 本地映射与投影错误 |
| 3 | **独立外部期末证据** | **导入覆盖是否遗漏** |

> 由同一份导入 BT 生成两次汇总**不算**第三份证据（验收 §4.3）。

第 3 份的取得顺序：

1. 优先使用**对应期间、范围与截止点的报告**（`ReportPort`）
2. 报告能力不可用时，在**可控静止区间**采集 Balance 快照，并保存"窗口内无其他资金变动"的证据
3. 两者都做不到 → 运行保持 `INCOMPLETE`

**当前 Balance API 快照不能冒充昨日历史期末**（PRD §11、AC-V1-29）。

## 4. 断言时点

| 时点 | 断言 |
|---|---|
| 每次已提交本地事务后 | I-01 平衡；I-02 唯一及本次原子关联；I-03 NORMAL 额度；I-04 上限；I-07 隔离；I-06 本地分配不超额 |
| 非法命令被拒绝后 | 无新增资金操作、预占、分润凭证、Outbox、银行匹配或余额变化；已有合法事务效果不被撤销 |
| 外部事实暂未完整时 | `UNKNOWN` / `WAITING_EVIDENCE` / `CONFLICT` 可解释；**不**断言外部余额必须相等，也**不**虚假 `PASS` |
| 有限输入执行完并排空任务后 | 已接受事件覆盖完整；模型、重建与投影一致；证据齐备时 I-05 / I-06 成立；未解决例外明确报告 |
| 无法安全自动恢复时 | 无无依据资金写入；存在持久升级任务与报警；**不**用无限重试假装收敛 |

## 5. 锁顺序（PR00 冻结）

多行不变量需要锁定稳定父记录/控制行。**全局固定顺序，按 rank 升序获取**：

| rank | 对象 | 说明 |
|---|---|---|
| 10 | `business_order` | |
| 20 | `payment`（支付控制行） | 退款/分润/争议的共同父行 |
| 30 | `refund_control` | |
| 40 | `dispute`（争议控制行） | |
| 50 | `share_allocation` | |
| 60 | `payout`（分配控制行） | |
| 65 | `bank_statement_line` | |
| 70 | `financial_event` | |
| 80 | `ledger_account` | **多个账户按 `ledger_account_id` 升序** |
| 85 | `balance_projection` | 同上，按稳定 ID 升序 |
| 90 | `outbox_event` | 仅 INSERT |

规则：

1. **只能按 rank 升序获取**；同 rank 内按主键升序（UUID 字节序，稳定）。
2. **纯账本业务可以跳过前面的业务锁**（例如只处理一个内部重分类）。
3. **但拿到账本锁（rank ≥ 70）之后，绝不能反向索取支付锁（rank ≤ 60）。** 不同处理入口反向加锁是死锁的主要来源。
4. 隔离级别：`READ COMMITTED` + 显式 `SELECT ... FOR UPDATE`，不依赖 `SERIALIZABLE` 的隐式保护。
5. 死锁（`40P01`）或序列化失败（`40001`）→ **重跑完整本地事务**并保持幂等；**不**重复发起外部资金请求。

典型路径示例：

```text
退款预占：      payment(20) → refund_control(30) → share_allocation(50)
                → financial_event(70) → ledger_account(80, 按 ID 升序) → outbox(90)

争议扣款入账：  payment(20) → dispute(40) → share_allocation(50)
                → financial_event(70) → ledger_account(80) → outbox(90)

银行匹配：      payout(60) → bank_statement_line(65)
                → financial_event(70) → ledger_account(80) → outbox(90)

纯 BT 入账：    financial_event(70) → ledger_account(80)      ← 合法跳过业务锁
                ✗ 之后再去锁 payment(20) —— 禁止
```

## 6. 夜间七项检查

每个启用账户按配置业务时区运行，固定 `runId`、输入高水位、账本 cutoff、外部证据 cutoff、规则版本、数据完整性与残差。

| 检查 | 对应不变量 | `FAIL` 条件 | `INCOMPLETE` 条件 |
|---|---|---|---|
| 试算平衡 | I-01、I-02 | 不平衡；已接受事件缺 Journal | — |
| 账户余额重建 | I-07 | 投影多加一次；来源跨域重复 | — |
| 退款预占老化 | I-03 | 超额；无告警的失联预占 | 外部未知保留状态 |
| 分润上限 | I-04 | 预占后超计提；乱序重复恢复 | — |
| BT 覆盖 | I-05、I-02 | 确定漏记/重复 | 缺页；范围不明 |
| PSP 余额核对 | I-05 | 完整证据下残差非零 | 缺独立期末证据 |
| payout 在途核对 | I-06 | 重复分配；已知短款未处理 | 银行缺证据 |

**缺证据不是 `PASS`。** 报告同时呈现未分类数、待证据数、失败数与完整性；"程序跑完了"不等于全部通过。禁止自动加 `OPENING_EQUITY` 或随机 adjustment 清零残差。
