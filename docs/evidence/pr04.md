## 关键实验的含义

`ProviderSimulatorReplayTest` 实际执行：Checkout 受理后丢响应 → 重启并原键恢复 → 客户完成 capture → Refund 受理后丢响应 → 原键两次恢复 → 模拟时钟到达保留窗口 → 再次提交相同退款键。

预期独立计数：6 次端口调用、3 个新接受操作、1 个会话、1 次扣款、2 次退款效果。最后两次退款是刻意演示**过期键盲目重发的风险**，不是宣称本地恢复器已经避免重复退款。PR07/PR11 将用这类场景验证“不盲目重发”的策略。
