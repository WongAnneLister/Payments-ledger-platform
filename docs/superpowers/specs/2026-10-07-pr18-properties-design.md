# PR18：独立资金模型与组合、并发验证

本期按用户“给我做 PR18”的指令执行已经冻结的 [PR18 需求](../../product/stripe-payment-ledger-codex-pr-prompts.md)。基线为 `8e1dc2e`，工作分支 `codex/pr18-properties`。不重新定义资金规则；上一轮真实账户闭环记录留在 main 工作目录，本期不用真实账户。

## 方案选择

采用测试目录中的独立整数模型、可复现生成器与 shrinker，加实际生产服务和真实 PostgreSQL 的逐步比对。单独对纯模型做随机测试无法验证生产实现；仅增加固定集成案例则无法探索组合。模型不能导入生产计算器，也不能把数据库结果回填为预期值。

建立 PaymentModel、RefundModel、RevenueShareModel、LedgerModel、PayoutModel、ReconciliationModel。模型自行维护已捕获 C、退款 R、预占 H、floor(max(C-R-H,0)*bps/10000)、分录、事件唯一性、PSP 变动及 payout 在途/银行分配。生产服务驱动器只翻译操作、执行真实服务、读取实际值。数据库只用于隔离 fixture 配置和只读断言；不直接伪造被验证业务效果。

生成合法和应拒绝操作，涵盖付款成功/拒绝/未知、退款预占/成功/失败、重复与旧状态、资金流水先于依赖、争议阻断及资金退回、分润重算、payout 出款/失败返还/银行 fixture 匹配、跨作用域和缺证据。网络故障使用 Fake/受控 Provider；业务事件与数据库约束是真实代码。恢复测试保持原 key，覆盖租约过期、旧 Worker 回写及 key 过期不得盲发。

默认 100 个可复现 case seeds、每序列最多 100 步；nightly 配置 1000 个 case seeds、最多 300 步。每个生成样本保存 seed、参数和完整操作列表；失败保存原序列、保持失败的缩小序列与真实状态快照。实际选择固定版本 PR18-1 的确定性语法生成器及保留依赖的操作删除收缩器，不新增 jqwik。收缩结果只表示当前语法内不能再删除单个操作，不声称数值或全局最小；实测敏感性清楚标为 mutation，不能冒充真实缺陷。

每个本地事务后检查 I-01 借贷平衡、I-02 唯一入账与有账覆盖、I-03 退款额度、I-04 分润 cap、I-07 隔离与重建。外部证据缺失时不宣称 I-05/I-06 已 PASS；完整窗口和一致 cutoff 后独立验证 PSP 和银行 fixture 对账。事件唯一键不独自证明无遗漏。

并发另设真实 PostgreSQL 测试：两份独立 API/Worker 服务对象与独立连接，通过屏障竞争同一支付控制行、分润重算及 payout 分配。记录 backend PID、结果、计数和余额，验证固定锁序、完整事务重试、同键去重与拒绝后无残留。串行序列不能代替并发；进程级故障矩阵留给 PR19。

## 交付与边界

新增测试、测试工具、CI 默认/夜间入口、版本记录、执行报告和操作手册。真实缺陷必须先复现再做最小生产修复，不改变模型/规则迎合实现。构建、隔离迁移、全部原回归、属性、并发、文档与 diff 检查均记录实际命令/输出，未运行范围明确 NOT RUN。PR18 不合入或推送 main，等待用户后续指令。
