# ADR-0008：余额重建口径

状态：Accepted（PR00 冻结） · 日期：2026-09-10

## 背景

独立重建余额是 I-07 与夜间检查的核心手段：绕开生产投影路径，从不可变分录重新算一遍余额，用来发现投影漂移。

但"从分录重建"有一个隐藏的双计陷阱：

```text
如果期初余额已经作为一张 OPENING Journal 入账，
而重建时又额外加上"期初快照"，
则期初被计算了两次。
```

反之，如果期初**没有**作为 Journal 入账，重建时只累计分录，就会**少**一个期初。

PRD FR-REC-01 明确警告："已有账户迁入必须提供核对过的期初快照和截止区间，**禁止全历史 BT 再加全额期初双计**"。验收 §3 要求 PR00 固定默认口径。

## 决策

**两种口径互斥，PR00 冻结默认为 `OPENING_JOURNAL`。**

| 口径 | 计算方式 | 何时使用 |
|---|---|---|
| **`OPENING_JOURNAL`（默认）** | 从 **0** 开始累计扫描集内**全部**不可变分录。期初（若非零）已作为 `L-OPENING` 凭证入账并**包含在扫描集中** | 本项目默认。控制账户从空测试账户起步，期初为 0，无需额外凭证 |
| `EXTERNAL_OPENING_SNAPSHOT` | **经核对的期初快照** + cutoff **之后**的分录 | 仅当期初**未**作为 Journal 计入扫描集时使用 |

### 强制要求

1. 每次重建运行**必须显式记录所用口径**（`rebuildMode` 字段），不允许隐式默认。
2. 使用 `EXTERNAL_OPENING_SNAPSHOT` 时，运行记录必须同时保存：期初快照来源、快照摘要、cutoff 时点、"该 cutoff 之前无分录进入扫描集"的验证结果。
3. **两种口径不得混用**。同一次运行中一部分科目用 A、另一部分用 B，视为严重缺陷。
4. 期初凭证（`L-OPENING`）的事件键为 `opening:{account_scope_hash}:{cutoff}`，天然幂等——**重复执行期初入账不会产生第二张凭证**（I-02）。

### 判定逻辑

```text
扫描集是否包含该 AccountScope 的 OPENING Journal？
   ├─ 是 ──► OPENING_JOURNAL：balance = Σ(所有分录)
   │          ✗ 不得再加期初快照
   └─ 否 ──► EXTERNAL_OPENING_SNAPSHOT：balance = 期初快照 + Σ(cutoff 后分录)
              ✗ 必须显式标记
              ✗ 必须证明 cutoff 前无分录混入
```

## 被否方案

| 方案 | 为什么否 |
|---|---|
| **总是"期初快照 + 全部分录"** | 期初已入账时必然双计。这正是 PRD 警告的"全历史 BT 再加全额期初"。 |
| **总是"从 0 累计全部分录"，不支持外部快照** | 无法支持"已有账户迁入"场景——迁入时历史分录不在本系统，从 0 累计会少掉全部历史。 |
| **不固定默认，每次运行自行推断** | 推断逻辑本身可能出错，且错误是静默的（余额差一个期初，看起来像"残差"而非"口径错误"）。显式记录使口径错误可被审计发现。 |
| **用 `OPENING_EQUITY` 余额自动补差** | 等于用期初科目掩盖残差。PRD §9.1 与验收 §8 均明确禁止"自动加 OPENING_EQUITY 或随机 adjustment 清零"。 |
| **允许同一运行内混用口径** | 不同科目口径不同时，总账试算不可解释。 |

## 后果

**正面**

- 空测试账户起步时期初为 0，默认口径下重建逻辑最简单：`balance = Σ(所有分录)`。
- 期初凭证走与其它凭证完全相同的不可变路径，享受同样的唯一性与审计保护。
- 口径写进运行记录，使"余额差一个期初"这类错误可被追溯为口径问题而非数据问题。

**负面与缓解**

| 负面 | 缓解 |
|---|---|
| 迁入场景需要额外的期初核对流程 | 本期从空账户起步，迁入场景仅作为 fixture 验证 |
| 两种口径增加测试面 | 两种口径各有明确 fixture；验收要求"另一种输入必须显式标记" |
| 期初凭证本身可能记错 | 期初凭证必须有"经核对"的外部证据来源，且走审批路径 |
