# 手算分录示例

版本：PR00 · 状态：冻结设计，未实施

关联：[验收 §5](../product/payment-platform-acceptance.md) · [账本科目](accounts.md) · [七项不变量](invariants.md) · [payout 状态机](../state-machines/payout.md) · [争议状态机](../state-machines/dispute.md)

## 0. 共同约定

- USD，最小单位整数，期初全零。
- 收款 10000，实际 charge fee 300，合作方比例 20%（2000 bps）。
- **所有数字都是 fixture，费用不是 Stripe 实际报价。**
- 每行代表一张平衡 Journal，或一次不涉及 PSP 的控制状态变化。
- 舍入政策：向下取整，各合作方独立计算，**余数归平台**。

> **路线 A 与路线 B 是不同的测试实例。** 争议、退款失败与 payout 失败均为独立分支，
> **不能**把各表事件串成同一笔现金路线。

## 1. 路线 A：收款 → 部分退款成功 → payout → 模拟银行到账

| 步骤 | 事实 | 借方 | 贷方 | 步骤后关键结果 |
|---|---|---|---|---|
| A1 | Charge BT：amount=10000, fee=300, net=9700 | `PSP_FUNDS` 9700；`PSP_FEE_EXPENSE` 300 | `SALES_REVENUE` 10000 | C=10000；PSP=9700；R=H=0 |
| A2 | 收款证据齐备，首次计提 | `PARTNER_SHARE_EXPENSE` 2000 | `PARTNER_PAYABLE` 2000 | cap=S=2000 |
| A3 | 预占退款 4000（同事务撤回分润） | `PARTNER_PAYABLE` 800 | `PARTNER_SHARE_EXPENSE` 800 | H=4000；R=0；eligibleBase=6000；cap=S=1200；**PSP 仍为 9700** |
| A4 | Refund BT：amount=−4000, fee=0 | `SALES_RETURNS` 4000 | `PSP_FUNDS` 4000 | H=0；R=4000；PSP=5700；**H→R 不重复撤回分润** |
| A5 | payout 本金 5700 的扣减 BT | `BANK_PAYOUT_IN_TRANSIT` 5700 | `PSP_FUNDS` 5700 | PSP=0；在途=5700；银行=0 |
| A6 | 模拟银行证据确认 5700 | `BANK_CASH` 5700 | `BANK_PAYOUT_IN_TRANSIT` 5700 | 在途=0；银行=5700；本金全额匹配 |

**可用性前置**：A5 只在 fixture 表明对应金额可出款且**有实际扣减 BT** 时发生。`pending→available` 不改变 A1～A4 的 PSP 总额。`payout.paid` 可以先到或后到，**它本身不产生 A6**。

### 1.1 手算核对

```text
退款额度：  R + H = 4000 + 0 = 4000 ≤ 10000 = C          ✓ I-03
分润：      eligibleBase = 10000 − 4000 − 0 = 6000
            cap = floor(6000 × 2000 / 10000) = 1200
            S = 2000 − 800 = 1200 ≤ 1200                  ✓ I-04
PSP：       0 + 9700 − 4000 − 5700 = 0
            还需与同截止点的独立提供方期末证据 0 比较      ✓ I-05（需外部证据）
payout：    5700 = 在途 0 + 确认银行本金 5700 + 返还 0     ✓ I-06
```

**期末余额试算**

| 借方科目 | 余额 | 贷方科目 | 余额 |
|---|---:|---|---:|
| `BANK_CASH` | 5700 | `SALES_REVENUE` | 10000 |
| `SALES_RETURNS` | 4000 | `PARTNER_PAYABLE` | 1200 |
| `PSP_FEE_EXPENSE` | 300 | | |
| `PARTNER_SHARE_EXPENSE` | 1200 | | |
| **借方合计** | **11200** | **贷方合计** | **11200** |

**发生额合计**：各 Journal 借方发生额合计 = 贷方发生额合计 = **28200**
（10000 + 2000 + 800 + 4000 + 5700 + 5700）。

> **28200（发生额）与 11200（期末净余额试算）是两个不同统计，不能混用。**

**演示净收益**：`10000 − 4000 − 300 − 1200 = 4500`。
银行账上的 5700 中仍含**未实付**的合作方应付 1200——**Stripe payout 没有结清分润**。

### 1.2 payout 失败分支（从 A5 开始，**不执行 A6**）

| 步骤 | 借方 | 贷方 | 结果 |
|---|---|---|---|
| A5' | `PSP_FUNDS` 5700 | `BANK_PAYOUT_IN_TRANSIT` 5700 | PSP=5700；在途=0；银行=0 |

守恒：`5700 = 在途 0 + 确认银行本金 0 + 返还 5700` ✓

**不得**再套用路线 A 的"银行=5700"。

## 2. 路线 B：退款失败恢复

新建独立 fixture，重复 A1/A2 的收款与首次计提，**不创建路线 A 的 payout**。初始 PSP=9700、S=2000。

| 步骤 | 控制状态与账务 | 结果 |
|---|---|---|
| B1 | 预占 4000；同事务借 `PARTNER_PAYABLE` 800、贷 `PARTNER_SHARE_EXPENSE` 800 | C=10000、R=0、H=4000；S=1200；PSP=9700 |
| B2 | 远端已受理但超时，退款 `UNKNOWN` | H 保持 4000；**不**补造退款 BT；**不**恢复分润、**不**新建退款 |
| B3 | 本分支收到扣减 BT：借 `SALES_RETURNS` 4000、贷 `PSP_FUNDS` 4000 | PSP=5700；R/H 仍按经核验状态更新，**不能用 BT 直接假装业务成功** |
| B4 | 明确 `FAILED`：幂等释放 H；无其它阻断时借 `PARTNER_SHARE_EXPENSE` 800、贷 `PARTNER_PAYABLE` 800 | R=0、H=0、eligibleBase=10000、S=2000；**失败状态本身不把 PSP 加回** |
| B5 | 新的失败返还 BT：借 `PSP_FUNDS` 4000、贷 `SALES_RETURNS` 4000 | PSP=9700；`SALES_RETURNS` 净额=0；原 charge fee 300 仍存在 |

B4 与 B5 **可以乱序到达**；缺依赖或矛盾进入待证据/调查。恢复分润还必须满足：无阻断争议、无未解决资金矛盾、已具备收款记账证据。重复 B4/B5 **不再**释放额度、计提或增加 PSP。

### 2.1 两个失败子用例的区别

| 子用例 | 步骤 | 最终 PSP | 最终 S | 账务历史 |
|---|---|---|---|---|
| 产生了扣减 BT 后失败 | B1、B2、B3、B4、B5 | 9700 | 2000 | 有一减一加的**真实**资金记录 |
| 产生扣减 BT **之前**就失败 | B1、B2、B4 | 9700 | 2000 | 无 B3/B5，**不制造**一减一加的假资金变动 |

**两者最终余额相同，但账务历史不同。** 这正是"不能用最终余额代替过程证据"的演示点。

### 2.2 B5 完成后的期末余额

| 借方科目 | 余额 | 贷方科目 | 余额 |
|---|---:|---|---:|
| `PSP_FUNDS` | 9700 | `SALES_REVENUE` | 10000 |
| `PSP_FEE_EXPENSE` | 300 | `PARTNER_PAYABLE` | 2000 |
| `PARTNER_SHARE_EXPENSE` | 2000 | | |
| **借方合计** | **12000** | **贷方合计** | **12000** |

银行与出款在途均为 0。发生额合计 = **21600**（10000+2000+800+4000+800+4000）。

## 3. 争议分支（从 B5 节点复制三个独立 fixture）

起点：PSP=9700、S=2000、R=H=0。

| 分支 | 分录与控制行为 | 最终可核验余额 |
|---|---|---|
| **开案但无扣款 BT** | 撤回全部 2000：借 `PARTNER_PAYABLE` 2000、贷 `PARTNER_SHARE_EXPENSE` 2000；存在阻断时 eligibleBase=0；inquiry/warning **无扣款证据不减少 PSP** | PSP=9700；S=0；普通退款被阻止；**不能凭状态构造争议应收** |
| **正式扣款后胜诉** | 扣款 BT：借 `DISPUTE_RECEIVABLE` 3000、借 `DISPUTE_FEE_EXPENSE` 1500、贷 `PSP_FUNDS` 4500；返还 BT：借 `PSP_FUNDS` 3000、贷 `DISPUTE_RECEIVABLE` 3000；证据齐备且无其它阻断后重新计提 2000 | 扣款后 PSP=5200；胜诉后 PSP=8200、应收=0、S=2000；**争议费 1500 无返还证据则保留** |
| **正式扣款后败诉** | 同样先扣款与撤回分润；`lost` 时借 `DISPUTE_LOSS` 3000、贷 `DISPUTE_RECEIVABLE` 3000，**PSP 不再扣款** | PSP=5200；应收=0；争议损失=3000；争议费=1500；S=0 |
| **上一败诉分支发生 late win** | 新返还 BT：借 `PSP_FUNDS` 3000、贷 `DISPUTE_LOSS` 3000（关联原损失）；证据齐备且无其它阻断后可重新计提 | PSP=8200；损失净额=0；应收=0；S=2000；**争议费仍=1500** |

**"开案但无扣款"可作为各争议生命周期的前置节点。胜诉与败诉互斥，late win 只能接在对应败诉分支之后。不能把正常胜诉返还与 late win 返还各加一次。**

### 3.1 手算核对（扣款后胜诉分支）

```text
扣款：  PSP = 9700 − 4500 = 5200
        应收 = 3000，争议费 = 1500
胜诉：  PSP = 5200 + 3000 = 8200
        应收 = 3000 − 3000 = 0
检查：  借方增量 3000(应收) + 1500(费) = 4500 = 贷方 PSP 4500   ✓ I-01
        返还：借 PSP 3000 = 贷 应收 3000                        ✓ I-01
```

### 3.2 分配优先级 microfixture

同一关联争议：**尚存应收 1000、已确认损失 2000**，收到本金返还 **3500**：

```text
借 PSP_FUNDS            3500
  贷 DISPUTE_RECEIVABLE  1000     ← 优先级 1：尚存应收
  贷 DISPUTE_LOSS        2000     ← 优先级 2：已确认损失
  贷 SUSPENSE             500     ← 优先级 3：超额待解释
                        ─────
  借方 3500 = 贷方 3500                                          ✓ I-01
```

**优先级固定为：尚存应收 → 已确认损失 → 超额待解释。不得直接贷损失 3500。**
超额差错未解决时，**不据此自动恢复分润**。

## 4. 已银行匹配又收到 payout 返还（冲突 fixture）

单独的冲突 fixture：原本金 5700 已匹配银行（A5 + A6 已完成，在途=0、银行=5700），然后发现真实返还 BT 5700。

| 步骤 | 借方 | 贷方 | 说明 |
|---|---|---|---|
| C1 | — | — | 锁定 payout 控制行，阻止超额分配与新自动出款；置 `CONFLICT` |
| C2 | `PSP_FUNDS` 5700 | `SUSPENSE` 5700 | 在途已为 0，**不把在途减成负数**；按暂记规则保留真实资金影响 |
| C3 | `SUSPENSE` 5700 | `BANK_CASH` 5700 | **仅在**取得银行退回证据后追加 |

最终：`BANK_CASH` 净到账 = 0，`PSP_FUNDS` 返还 = 5700，`SUSPENSE` 净额 = 0。

```text
✓ 两份事实都保留（原银行入账 Journal 与原 payout Journal 均不删除）
✗ 不能把"确认到账 5700 + 确认返还 5700"都算成该 payout 的本金分配
✗ 没有银行证据时不能先假定银行现金已减少 —— 停在 C2，状态保持 CONFLICT
```

## 5. 未分类 payments 域资金（Suspense）

已核验账户/环境/币种且**确定属于 payments 域**，但业务类型暂不识别：

| 输入 | 分录 |
|---|---|
| 已知净增 700 | 借 `PSP_FUNDS` 700；贷 `SUSPENSE` 700 |
| 已知净减 700 | 借 `SUSPENSE` 700；贷 `PSP_FUNDS` 700 |

后续查明业务分类且无需额外 PSP 变动时，以**关联的新凭证**完成重分类；**不重新记 PSP，不修改原 Journal**。

> 700 只是输入，**不代表** Stripe 的某个真实交易类型。
> 其它 balance domain、FX 或归属不足 → **隔离观察**，不映射到 payments PSP。

## 6. 符号与方向一致性自检

所有示例满足：

| 检查 | 结果 |
|---|---|
| 每张 Journal 借方合计 = 贷方合计 | ✓ |
| 每张 Journal 至少两条有效分录 | ✓ |
| 单张 Journal 内币种一致（全部 USD） | ✓ |
| 无零额分录 | ✓ |
| 资产增加记借方、收入增加记贷方、负债增加记贷方 | ✓ |
| 退款记 `SALES_RETURNS` 借方（收入抵减），不冲减 `SALES_REVENUE` | ✓ |
| 败诉不产生第二次 `PSP_FUNDS` 贷方 | ✓ |
| 预占（H）不产生任何分录 | ✓ |
